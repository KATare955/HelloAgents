## 一、审核意见①：桶1×跨场景·竞品对比（b1cs_c00 / b1cs_c10）

### 审核现象

用户问题是竞品对比（"帮我对比一下 E5 Sportback 2025款 旗舰quattro型"），但模型 Thought 与工具调用是"查优惠、算月供"，仅最终答复文本正确。

### 根因

Python 循环闭包陷阱：`gen_templates_full_b1b2.py` 中 b1cs_c 循环内定义的 `build` 引用循环变量 `r`，未通过默认参数绑定。所有 build 共享同一个闭包帧 cell，执行时读到的是**后续 b1cs_d 循环覆写后的值**（"用户想了解优惠和月供……"），导致 20 条样本的 Thought 全部串位成 b1cs_d 的内容。

**修改前：**

```python
def build(q_final: str, a_final: str) -> List[Dict[str, Any]]:   # r 未绑定
```

**修改后（b1b2.py L410）：**

```python
def build(q_final: str, a_final: str, r=r) -> List[Dict[str, Any]]:
```

### 波及范围

数据实证：b1cs_c 20 条样本中 20 条的 Thought 均为 b1cs_d 的"优惠和月供"文本（20/20 串位）。

### 修复后验证

- 模板级重放：20 条 Thought 全部为"用户只给了本车车型，未说明要与哪款竞品对比……先询问对比对象"
- T9 全量轨迹自洽：970 条重放比对 0 不一致
- T8 视图 b1cs_c00/c10 已抽中且轨迹正确（竞品反问，无工具调用）

## 二、审核意见②：b3fn_b00 自动代入上海

### 审核现象

用户题面未提到上海（"E5 Sportback 2025款 先锋quattro型现在有啥优惠活动啊？贷款的话……"），模型却查询上海优惠活动。按规则应缺省全国。

### 根因

`b3fn_b` 模板硬编码 `query_discount_policy(car_model=..., region="上海")`；同类 `b1cs_d`（桶1×跨场景·金融+优惠组合）同样硬编码 region="上海"。mock 中上海口径多 1 项"低息贷款 5000 元"，答复数据也与全国口径不符。

### 修改内容（修改前 → 修改后）

**b3fn_b（b3b4b5.py L166-180）：**

- 工具调用：`{"car_model": "E5 Sportback", "region": "上海"}` → `{"car_model": "E5 Sportback"}`（region 缺省 → mock 默认全国）
- Thought：`"先查上海地区优惠…"` → `"用户想了解优惠并计算月供。先查全国通用优惠，再按默认方案计算月供，优惠与月供都要在答复中呈现。"`
- 答复：【上海地区优惠】→【全国通用优惠】（全国口径实跑 2 项：限时优惠 20000 + 旧车置换补贴 10000）
- 设计意图：`"多跳：查优惠（全国口径，未指定地区不代入）→算月供，两跳结果合并呈现"`

**b1cs_d（b1b2.py L432-445，同类）：**

- 工具调用：`query_discount_policy` 去掉 `region="上海"` → 全国口径
- Thought/答复/设计意图同步改为全国口径（"【全国通用优惠】"）

### 波及范围

b1cs_d 20 条 + b3fn_b 15 条 = 35 条，全部改为全国口径。

### 合规性说明

题面显式含地区的场景不受影响、仍传 region：b3cs（题面含城市）、b5_discount 上海口径组（题面显式"上海"）。该规则与 b1cs_a（优惠缺 region→默认全国正例）保持一致。

def build(q_final: str, a_final: str, r1=r1, err_args=err_args, err_obs=err_obs,
          r2=r2, fix_args=fix_args, fix_obs=fix_obs) -> List[Dict[str, Any]]:

## 四、审核意见④：b5tp_a00 / a20 无数据播报 0 元

### 审核现象

题面问近 30 天（或 180 天）成交价，mock 无该组合数据，模型直接答复"平均成交价为 0 元（其中最低 0 元，最高 0 元）"，应答质量差。应设计反问或兜底方案（如改查近 90 天）。

### 根因

mock `query_transaction_price` 仅有数据组合 = 4 车 90 天 + 旗舰quattro型 30 天。模板 b5tp_a 对 (车, 30/180 天) 无数据组合直接格式化 `avg_price=0`。

### 修复方案：两跳兜底（b3b4b5.py L707-733 `_tp_sample`）

- 第 1 跳：按题面天数查询 → 实跑返回 `sample_count=0`
- 第 2 跳：新增 Thought"近 X 天暂无成交数据。为提供有效参考，改查官方口径的近90天成交价。" → 改查 `days=90`
- 答复改为："{车}近 X 天暂无历史成交记录（样本 0 条）。已为您改查近90天：平均成交价…（最低…/最高…），趋势…，样本…条。建议：…"

**修改前（0 元播报）：**

```python
a = f"{car}近{days}天：平均成交价{d['avg_price']}元（最低{d['min_price']}元/最高{d['max_price']}元）…"  # d 为 0 样本数据
```

**修改后：**

```python
if d.get("sample_count", 0) == 0:
    obs90 = run_tool_parsed("query_transaction_price", {"car_model": car, "days": 90})
    d90 = obs90["data"]
    r2 = f"近{days}天暂无成交数据。为提供有效参考，改查官方口径的近90天成交价。"
    a = (f"{car}近{days}天暂无历史成交记录（样本0条）。\n"
         f"已为您改查近90天：平均成交价{d90['avg_price']}元（最低…/最高…），趋势…，样本…条。\n"
         f"建议：{d90['recommendation']}")
```

### 波及范围

b5tp_a 40 条中 24 条受影响（(车, 30/180 天) 无 mock 数据组合），全部改为两跳兜底；16 条有数据组合保持单跳不变。

### 修复后验证

- 模板级重放：24 条兜底样本的 0 元播报为 0 条；兜底 r2 中 days 与题面一致
- T8 视图 b5tp_a00/a20/a02 已抽中：均为两跳兜底形态（"近 X 天暂无历史成交记录（样本0条）→ 已改查近90天 → 给出参考价与建议"）
